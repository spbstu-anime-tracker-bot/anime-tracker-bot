# Требования к проекту "Anime Tracker and Advisor Bot"

## 1. Введение
**Anime Tracker and Advisor Bot** — это Telegram-бот, предназначенный для ведения персональных списков аниме (просмотренное/планируемое) и получения интеллектуальных рекомендаций. Бот использует локальную базу данных на основе датасета MyAnimeList для поиска информации и LLM-модель Gigachat для формирования персонализированных советов на основе оценок пользователя.

---

## 2. Функциональные требования

### 2.1. Аутентификация и профиль пользователя
*   **Автоматическая регистрация**: Пользователь автоматически регистрируется в системе при первой отправке команды `/start`. Идентификация происходит по уникальному **Telegram ID**.
*   **Запись в БД**: При регистрации создается запись в таблице пользователей, содержащая Telegram ID и время регистрации.
*   **Доступ к функциям**: Весь функционал бота доступен сразу после автоматической регистрации без дополнительных шагов.

### 2.2. Поиск и отображение аниме

#### 2.2.1. Поиск по названию
*   **Команда**: `/search <название>`
*   **Логика**: Поиск в БД всех аниме, названия которых содержат введенную строку (регистронезависимо). Результаты сортируются по популярности.

#### 2.2.2. Расширенный поиск (фильтрация)
*   **Команда**: `/search_by <параметры>`
*   **Параметры**: Жанр, тип (TV, Movie и т.д.), год выхода. Можно указать до 3-х критериев через запятую в любом порядке.
*   **Обработка ошибок**: Если критерий не распознан, бот отвечает: *"Введён несуществующий критерий — '{Значение}'"*.

#### 2.2.3. Ранжирование результатов
Результаты поиска и рекомендаций всегда сортируются по метрике **Popularity**, рассчитываемой по формуле:

$$Popularity = Rating \cdot \log_{10}{Users}$$

#### 2.2.4. Интерфейс отображения (Карточки)
Результаты выводятся в виде страниц (до 5 карточек на одну страницу), где каждая карточка является отедльным сообщением.
*   **Состав карточки**: Название, описание, рейтинг, жанры, тип, количество эпизодов и дата выхода.
*   **Интерактивные кнопки**: 
    *   "Добавить в просмотренные" / "Удалить из просмотренных"
    *   "Добавить в отслеживаемые" / "Удалить из отслеживаемых"
    *   "Поставить оценку" (для просмотренных).
*   **Навигация**: Кнопки "Предыдущая" и "Следующая" под списком карточек.

### 2.3. Управление списками (Tracker)
*   **Просмотр списков**: Команды `/list_viewed` и `/list_to_view` выводят соответствующие списки пользователя в формате карточек.
*   **Оценка контента**: При нажатии "Поставить оценку" доступен выбор от 1 до 10. Оценка сохраняется в БД и используется для формирования рекомендаций.

### 2.4. Персональные рекомендации (Advisor)
*   **Команда**: `/advise`
*   **Алгоритм работы**:
    1. Если пользователь не добавлял новых оценок, выдаются закэшированные прошлые рекомендации.
    2. Система анализирует оценки пользователя.
    3. Формируется запрос к LLM (Gigachat) на получение 10 рекомендаций.
    4. Бот сопоставляет ответы LLM с локальной базой данных.
    
*   **Таймаут**: Если LLM не отвечает в течение 1 минуты, выводится сообщение: *"Функция временно недоступна. Попробуйте повторить запрос через некоторое время"*.

### 2.5. Обработка ошибок
*   **Пустой результат**: Если аниме не найдены: *"Аниме не найдены"*.
*   **Некорректный ввод**: На сообщения, не являющиеся командами, или на неизвестные команды бот выводит соответствующее предупреждение.

## 3. Общие требования к проекту

### 3.1. Репозиторий и документация
*   **GitHub**: Весь исходный код должен находиться в репозитории.
*   **README.md**: Содержит описание проекта, инструкцию по развертыванию и ссылку на Docker-образ.
*   **Файлы спецификаций**: В репозитории должны присутствовать `requirements.md` и `architecture.md`.

### 3.2. Сборка и развертывание
*   **Локальный запуск**: Поддержка запуска через среду разработки.
*   **Docker**: Основной способ запуска — через `docker-compose`. Образ должен быть опубликован на Docker Hub.

## 4. Сценарии использования (Use Cases)

| Сценарий | Описание действий |
| :--- | :--- |
| **Поиск и добавление** | Пользователь вводит `/search наруто`, получает список, нажимает кнопку "Добавить в отслеживаемые" на нужной карточке. |
| **Получение рекомендации** | Пользователь вводит `/advise`. Система находит похожих по оценкам пользователей/аниме, обращается к LLM и выдает ранжированный список. |
| **Ошибка критерия** | Пользователь вводит `/search_by 1997, МКН`. Бот распознает год, но выдает ошибку на неизвестный параметр "МКН". |

## 5. Технический стек
*   **Язык**: Java 25
*   **Фреймворк**: Spring 7
*   **Сборка**: Gradle
*   **База данных**: PostgreSQL
*   **Брокер сообщений**: Kafka
*   **Контейнеризация**: Docker, Docker Compose
*   **LLM API**: Gigachat
*   **Данные**: MyAnimeList Dataset (Kaggle)
